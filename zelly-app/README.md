# Zelly — ระบบสร้างร้านค้าออนไลน์หลายร้าน (เวอร์ชันใช้งานจริง รอบที่ 3)

Zelly ให้เจ้าของร้านสมัครสมาชิก สร้างหลายร้าน จัดการสินค้า/สต็อก/คูปอง/สมาชิก รับออเดอร์จากลูกค้าผ่านลิงก์ร้าน (`/s/ชื่อร้าน`) แพ็กของ (มีเว็บแคมถ่ายรูปตอนแพ็ก) และให้ Super Admin ดูแลผู้ใช้/แพ็กเกจ/การชำระเงิน

- ฝั่งเซิร์ฟเวอร์: Node.js (ไม่ต้องใช้ framework) + ฐานข้อมูล **MySQL** (ของ Hostinger)
- ฝั่งหน้าเว็บ: ไฟล์เดียว `public/index.html` (ภาษาลาว / ไทย / อังกฤษ)
- ไม่มีข้อมูลตัวอย่าง: ทุกอย่างเริ่มว่าง สมัครแล้วใช้งานจริงได้เลย

## ขอบเขต (ใช้งานได้แล้ว)

## วิธีติดตั้งบน Hostinger (Node.js Web App + GitHub + MySQL)

### 1) ขึ้น GitHub
```bash
cd zelly-app
git init && git add . && git commit -m "Zelly v1"
git branch -M main
git remote add origin https://github.com/<ชื่อคุณ>/zelly.git
git push -u origin main
```
(หรือสร้าง repo ว่างบน github.com แล้วลากไฟล์ทั้งหมดในโฟลเดอร์นี้อัปโหลดผ่านหน้าเว็บ — ไม่ต้องอัปโหลด `node_modules`, `.env`, `data`)

### 2) สร้างฐานข้อมูล MySQL
hPanel → **Databases → Management** → สร้าง Database + User + Password → จดค่า
`ชื่อฐานข้อมูล`, `ชื่อผู้ใช้`, `รหัสผ่าน`, `MySQL hostname` (ปกติคือ `localhost` ให้ดูค่าที่ hPanel แสดง)

### 3) สร้างเว็บ Node.js
hPanel → **Websites → Add Website → Node.js Apps → Import Git Repository** → เลือก repo/branch `main`
- Node version: **20 หรือ 22**
- Build command: ปล่อยว่าง (หรือ `npm install`)
- Start command: `npm start`  · Entry file: `server.js`

### 4) ตั้ง Environment variables (ในหน้า Node.js App → Environment variables)

| ชื่อ | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| `DB_HOST` | `localhost` | จาก hPanel |
| `DB_PORT` | `3306` | |
| `DB_USER` | `u123456789_zelly` | |
| `DB_PASSWORD` | `********` | |
| `DB_NAME` | `u123456789_zelly` | |
| `ADMIN_EMAIL` | `you@example.com` | อีเมล Super Admin คนแรก |
| `ADMIN_PASSWORD` | `รหัสผ่านที่เดายาก` | ใช้ตอนเริ่มครั้งแรกเท่านั้น |
| `NODE_ENV` | `production` | |
| `APP_URL` | `https://โดเมนของคุณ` | ใช้ทำลิงก์ในอีเมล (ไม่ตั้งก็ได้ อีเมลจะไม่มีปุ่มลิงก์) |
| `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` `SMTP_FROM` | ดูหัวข้อ "อีเมล" | ไม่ตั้ง = ปิดการส่งอีเมล (ระบบอื่นทำงานปกติ) |
| `PHAJAY_SECRET_KEY` `PHAJAY_WEBHOOK_KEY` | ดูหัวข้อ "ชำระออนไลน์" | ไม่ตั้ง = ซ่อนปุ่มชำระออนไลน์ (ใช้โอน+สลิปเหมือนเดิม) |

กด **Deploy / Restart** — ตารางในฐานข้อมูลถูกสร้างอัตโนมัติ ถ้าลืมตั้ง `DB_HOST` แอปจะหยุดพร้อมข้อความบอก (กันข้อมูลหายตอน deploy ใหม่)

### 5) เปิดใช้งาน
1. เปิดโดเมน (ต้องเป็น **HTTPS** เพื่อให้เว็บแคมทำงาน — Hostinger เปิด SSL ฟรีให้)
2. เข้าสู่ระบบด้วย `ADMIN_EMAIL` / `ADMIN_PASSWORD` → ไปแท็บ **นโยบาย** ใส่บัญชีธนาคาร/QR สำหรับรับค่าแพ็กเกจ, ราคาแพ็กเกจ, เบอร์ติดต่อ และแท็บ **Affiliate** เพื่อเปิด/ตั้งเปอร์เซ็นต์ค่าคอมมิชชัน
3. ตรวจสุขภาพระบบที่ `https://โดเมนของคุณ/healthz` ต้องได้ `{"ok":true,"db":"mysql"}`
4. สมัครเป็นเจ้าของร้านทดสอบ → สร้างร้าน → เปิดลิงก์ `https://โดเมนของคุณ/s/ชื่อร้าน` ในหน้าต่างไม่ระบุตัวตนเพื่อลองสั่งซื้อ

ตรวจการเชื่อมต่อฐานข้อมูลจาก SSH ได้ด้วย `npm run dbcheck`

## ติดตั้งเป็นแอป (PWA)
- เปิดเว็บบน **HTTPS** (Hostinger เปิด SSL ให้) แล้วจะมีปุ่ม **"ติดตั้งแอป"** ลอยมุมซ้ายล่าง (Android/Chrome/Edge/เดสก์ท็อป กดแล้วติดตั้งทันที; iPhone/iPad แสดงวิธี "เพิ่มไปยังหน้าจอโฮม" ของ Safari) กด × เพื่อซ่อน 7 วัน
- หน้าแอดมิน/เจ้าของร้านติดตั้งเป็นแอป **Zelly**; หน้าร้านลูกค้า `/s/ชื่อร้าน` ติดตั้งเป็นแอป **ของร้านนั้น** (ชื่อร้าน, สีธีมของร้าน) — เจ้าของส่งลิงก์ให้ลูกค้ากดติดตั้งไว้สั่งซื้อซ้ำได้
- แอปไม่เก็บหน้าเว็บหรือข้อมูลไว้ในเครื่อง (ราคา/สต็อกสดเสมอ) ถ้าไม่มีอินเทอร์เน็ตจะแสดงหน้า "ออฟไลน์" แทน — ยังไม่รองรับใช้งานออฟไลน์ และไม่มีการแจ้งเตือน push
- ไอคอนอยู่ที่ `public/icons/` (เปลี่ยนเป็นโลโก้ใหม่ได้โดยแทนที่ไฟล์ชื่อเดิม); ถ้าแก้ `public/sw.js` ให้เปลี่ยนเลขเวอร์ชัน `V` ในไฟล์ด้วย

## ชำระค่าแพ็กเกจออนไลน์ (BCEL OnePay QR ผ่าน PhaJay)

**หลักการ:** BCEL ไม่มี API สาธารณะให้ร้านค้าเชื่อมต่อโดยตรง จึงใช้ตัวกลางชำระเงิน [PhaJay](https://phajay.co) (รองรับ QR ของ BCEL OnePay) — ผู้ใช้สแกน QR ด้วยแอป **BCEL One** เท่านั้น (ไม่ใช่ QR กลาง LAO QR). ถ้าภายหลังทำสัญญากับ BCEL/LAPNet โดยตรง ให้แก้เฉพาะไฟล์ `lib/payments.js` (มี 4 ฟังก์ชัน: `online`, `createQr`, `status`, `verifyWebhook`) ส่วนอื่นไม่ต้องแก้

**ขั้นตอนเปิดใช้งาน**
1. สมัครที่ https://portal.phajay.co แล้วทำ KYC (ระหว่างยังไม่ผ่าน KYC ใช้ `devSecretKey` ทดสอบได้)
2. ไปหน้า Key Management คัดลอก **secretKey** (หรือ devSecretKey ตอนทดสอบ)
3. ใน Hostinger → Environment variables ใส่
   - `PHAJAY_SECRET_KEY` = secretKey (หรือ devSecretKey)
   - `PHAJAY_WEBHOOK_KEY` = (ไม่บังคับ) คีย์ที่ PhaJay ใช้เซ็น webhook ถ้าต่างจากด้านบน คั่นหลายค่าด้วย `,` — ระบบยอมรับทั้ง `PHAJAY_SECRET_KEY` และ `PHAJAY_DEV_SECRET_KEY` อยู่แล้ว เพื่อไม่ให้พังตอนเปลี่ยนจาก dev เป็น KYC จริง
   - **โหมดทดสอบ (sandbox):** ถ้าใช้คีย์ทดสอบ ให้ตั้ง `PHAJAY_SANDBOX=1` ด้วย (ระบบจะเรียก `/v1/api/test/payment/...` ตามเอกสาร PhaJay) และ QR ทดสอบต้องสแกนด้วยแอป **PhaJay** ไม่ใช่แอปธนาคารจริง. คีย์ทดสอบใช้กับ endpoint จริง (production) ไม่ได้ และ secretKey จริงจะออกให้หลังผ่าน KYC เท่านั้น — เมื่อสร้าง QR ไม่ได้ หน้าจอจะแสดงเหตุผลจาก PhaJay ในวงเล็บ
   - (ไม่บังคับ) `PHAJAY_BANK=bcel` (ค่าเริ่มต้น), `PHAJAY_BASE` (ค่าเริ่มต้น `https://payment-gateway.phajay.co`)
4. ในพอร์ทัล PhaJay ตั้ง **Webhook URL** เป็น `https://โดเมนของคุณ/api/webhooks/phajay`
5. Restart แอป → เข้าสู่ระบบเป็น Super Admin → แท็บ **นโยบาย** ต้องเห็น "ชำระออนไลน์ … พร้อมใช้งาน"

**การทำงาน:** เจ้าของร้านกด "ชำระออนไลน์ทันที" → เซิร์ฟเวอร์สร้าง QR (ยอดคำนวณที่เซิร์ฟเวอร์) → ผู้ใช้สแกนจ่าย → หน้าจอเช็กสถานะทุก 3 วินาที และ PhaJay ส่ง webhook มาด้วย → เซิร์ฟเวอร์ตรวจลายเซ็น (HMAC-SHA256 บน raw body) และ **ถามสถานะจริงกับ PhaJay อีกครั้ง** (ต้อง `isPaid` + `PAYMENT_COMPLETED` + ยอด ≥ ยอดคำขอ) ก่อนเปิดแพ็กเกจ → ต่ออายุ/เปลี่ยนแพ็กเกจ, บันทึกการชำระ, ค่าคอมมิชชัน Affiliate, ส่งใบเสร็จทางอีเมล. เรียกซ้ำกี่ครั้งก็ไม่เปิดซ้ำ. ถ้าลูกค้าจ่ายหลังคำขอหมดเวลา ระบบยังเปิดแพ็กเกจให้ (เงินเข้าแล้ว). วิธีโอน+สลิปยังใช้ได้ควบคู่

## อีเมล (SMTP ของ Hostinger)
สร้างกล่องอีเมลใน hPanel → Emails (เช่น `no-reply@โดเมนของคุณ`) แล้วตั้ง
```
SMTP_HOST=smtp.hostinger.com
SMTP_PORT=465            # 465 = SSL, หรือ 587 = STARTTLS (ระบบเลือกให้ตามพอร์ต)
SMTP_USER=no-reply@โดเมนของคุณ
SMTP_PASS=รหัสผ่านกล่องอีเมล
SMTP_FROM=Zelly <no-reply@โดเมนของคุณ>
```
จากนั้นเข้า Super Admin → **นโยบาย** → กด "ส่งอีเมลทดสอบหาฉัน". ถ้าไม่ผ่านจะแสดงข้อความจากเซิร์ฟเวอร์อีเมล. อีเมลส่งแบบเบื้องหลัง (ลองซ้ำ 2 ครั้ง) ไม่ทำให้หน้าเว็บช้า; เตือนใกล้หมดอายุตรวจทุกชั่วโมง (ส่งแต่ละขั้นครั้งเดียว). ภาษาของอีเมลตามภาษาที่ผู้รับใช้ล่าสุดตอนล็อกอิน/สลับภาษา. Hostinger จำกัดจำนวนอีเมลต่อชั่วโมงตามแพ็กเกจโฮสต์ — ถ้าร้านเยอะมากควรย้ายไปใช้บริการส่งอีเมลเฉพาะทาง (แก้ไฟล์ `lib/mailer.js` ไฟล์เดียว)

## รันในเครื่อง (ไม่ต้องมี MySQL)
```bash
npm install          # ติดตั้ง mysql2 (ใช้เฉพาะตอนต่อ MySQL)
node server.js       # ใช้ไฟล์ SQLite ที่ data/zelly.sqlite  (ต้อง Node 22.5+)
npm test             # ทดสอบ logic + API
npm run test:e2e     # ทดสอบบนเบราว์เซอร์ (ต้องมี playwright)
node test/e2e_pay.js # ทดสอบหน้าชำระออนไลน์บนเบราว์เซอร์ (ใช้ตัวกลางจำลอง)
node test/e2e_pwa.js # ทดสอบการติดตั้งแอป (PWA)
node test/e2e_wiz.js # ทดสอบ URL แยกหน้าสมัคร / ปุ่มย้อนกลับ / ร่างข้อมูล / เปลี่ยนรหัสผ่าน
```
เปิด http://localhost:3000 — ถ้าไม่ตั้ง `ADMIN_PASSWORD` ระบบสุ่มรหัสให้และพิมพ์ในหน้าจอ terminal

## ข้อควรรู้
- **รันแค่ 1 instance** (การล็อกเพื่อกันข้อมูลชนกันอยู่ในหน่วยความจำของโปรเซสเดียว) ซึ่งเพียงพอสำหรับ Node.js Web App ของ Hostinger
- ข้อมูลร้านบันทึกอัตโนมัติ ~1 วินาทีหลังแก้ไข (รวมข้อมูลจากหลายอุปกรณ์/พนักงานแบบรายรายการ ไม่ทับกัน) หากเน็ตหลุดจะมีแถบ "ยังบันทึกไม่ได้" และลองใหม่เอง
- รูปภาพ (สินค้า สลิป รูปแพ็ก) เก็บในตาราง `blobs` ของ MySQL สูงสุด 4MB/รูป — ถ้าใช้หนักมาก ควรเพิ่มพื้นที่ฐานข้อมูลหรือย้ายไปเก็บไฟล์ภายหลัง
- หน้าเว็บโหลดไลบรารี QR จาก cdnjs และฟอนต์จาก Google Fonts (ถ้าโหลดไม่ได้ QR จะไม่แสดง แต่ส่วนอื่นทำงานปกติ)
- **สำรองข้อมูล**: hPanel → phpMyAdmin → Export ฐานข้อมูลเป็นประจำ
- ตั้ง `TRUST_PROXY=0` ถ้ารันโดยไม่มี reverse proxy (ค่าเริ่มต้นเชื่อ `X-Forwarded-For` เพื่อจำกัดอัตราต่อ IP)
- ระบบชำระออนไลน์และอีเมล **ทดสอบกับตัวจำลอง (mock) ของ PhaJay และ SMTP เท่านั้น** ยังไม่ได้ลองกับบัญชีจริง — ให้ทดสอบด้วย devSecretKey และกด "ส่งอีเมลทดสอบ" ก่อนเปิดจริง และตรวจว่า PhaJay ยังใช้รูปแบบ webhook/ลายเซ็นตามเอกสารปัจจุบัน
- ฝั่ง MySQL ผ่านการเขียนแบบเดียวกับ SQLite แต่ **ยังไม่ได้ทดสอบกับ MySQL จริง** ในสภาพแวดล้อมที่พัฒนา — ให้ทำ checklist ในข้อ 5 ก่อนเปิดให้ลูกค้าจริง

## โครงสร้างไฟล์
```
server.js            เซิร์ฟเวอร์ + ไฟล์หน้าเว็บ + งานล้างออเดอร์หมดเวลา
lib/                 db (MySQL/SQLite), model (กติกาธุรกิจ), diff (ซิงก์ข้อมูล), session, util, blobs, payments (PhaJay), mailer (SMTP), notify (เทมเพลตอีเมล 3 ภาษา)
routes/              account (สมัคร/ล็อกอิน/พนักงาน/แพ็กเกจ), billing (ชำระออนไลน์/webhook/เตือนหมดอายุ), sync (บันทึกข้อมูลร้าน), public (หน้าร้านลูกค้า)
public/index.html    หน้าเว็บทั้งหมด (สร้างจากซอร์สของต้นแบบ)
scripts/dbcheck.js   ตรวจ DB    test/   ชุดทดสอบ
```
