# Zelly — ระบบสร้างร้านค้าออนไลน์หลายร้าน (เวอร์ชันใช้งานจริง รอบที่ 1)

Zelly ให้เจ้าของร้านสมัครสมาชิก สร้างหลายร้าน จัดการสินค้า/สต็อก/คูปอง/สมาชิก รับออเดอร์จากลูกค้าผ่านลิงก์ร้าน (`/s/ชื่อร้าน`) แพ็กของ (มีเว็บแคมถ่ายรูปตอนแพ็ก) และให้ Super Admin ดูแลผู้ใช้/แพ็กเกจ/การชำระเงิน

- ฝั่งเซิร์ฟเวอร์: Node.js (ไม่ต้องใช้ framework) + ฐานข้อมูล **MySQL** (ของ Hostinger)
- ฝั่งหน้าเว็บ: ไฟล์เดียว `public/index.html` (ภาษาลาว / ไทย / อังกฤษ)
- ไม่มีข้อมูลตัวอย่าง: ทุกอย่างเริ่มว่าง สมัครแล้วใช้งานจริงได้เลย

## ขอบเขตรอบที่ 1 (ใช้งานได้แล้ว)

| ส่วน | สถานะ |

| ออเดอร์ → แพ็ก (เว็บแคม) → จัดส่ง, ยกเลิกอัตโนมัติเมื่อหมดเวลาโอน | ✅ |

## วิธีติดตั้งบน Hostinger (Node.js Web App + GitHub + MySQL)

### 1) ขึ้น GitHub
```bash
cd zelly-app
git init && git add . && git commit -m "Zelly v1"
git branch -M main
git remote add origin https://github.com/<ชื่อคุณ>/zelly.git
git push -u origin main
```
(หรือสร้าง repo ว่างบน github.com แล้วลากไฟล์ทั้งหมดในโฟลเดอร์นี้อัปโหลดผ่านหน้าเว็บ — ไม่ต้องอัปโหลด `node_modules`, `.env`, `data`)

### 2) สร้างฐานข้อมูล MySQL
hPanel → **Databases → Management** → สร้าง Database + User + Password → จดค่า
`ชื่อฐานข้อมูล`, `ชื่อผู้ใช้`, `รหัสผ่าน`, `MySQL hostname` (ปกติคือ `localhost` ให้ดูค่าที่ hPanel แสดง)

### 3) สร้างเว็บ Node.js
hPanel → **Websites → Add Website → Node.js Apps → Import Git Repository** → เลือก repo/branch `main`
- Node version: **20 หรือ 22**
- Build command: ปล่อยว่าง (หรือ `npm install`)
- Start command: `npm start`  · Entry file: `server.js`

### 4) ตั้ง Environment variables (ในหน้า Node.js App → Environment variables)

| ชื่อ | ตัวอย่าง | หมายเหตุ |
|---|---|---|
| `DB_HOST` | `localhost` | จาก hPanel |
| `DB_PORT` | `3306` | |
| `DB_USER` | `u123456789_zelly` | |
| `DB_PASSWORD` | `********` | |
| `DB_NAME` | `u123456789_zelly` | |
| `ADMIN_EMAIL` | `you@example.com` | อีเมล Super Admin คนแรก |
| `ADMIN_PASSWORD` | `รหัสผ่านที่เดายาก` | ใช้ตอนเริ่มครั้งแรกเท่านั้น |
| `NODE_ENV` | `production` | |

กด **Deploy / Restart** — ตารางในฐานข้อมูลถูกสร้างอัตโนมัติ ถ้าลืมตั้ง `DB_HOST` แอปจะหยุดพร้อมข้อความบอก (กันข้อมูลหายตอน deploy ใหม่)

### 5) เปิดใช้งาน
1. เปิดโดเมน (ต้องเป็น **HTTPS** เพื่อให้เว็บแคมทำงาน — Hostinger เปิด SSL ฟรีให้)
2. เข้าสู่ระบบด้วย `ADMIN_EMAIL` / `ADMIN_PASSWORD` → ไปแท็บ **นโยบาย** ใส่บัญชีธนาคาร/QR สำหรับรับค่าแพ็กเกจ, ราคาแพ็กเกจ, เบอร์ติดต่อ
3. ตรวจสุขภาพระบบที่ `https://โดเมนของคุณ/healthz` ต้องได้ `{"ok":true,"db":"mysql"}`
4. สมัครเป็นเจ้าของร้านทดสอบ → สร้างร้าน → เปิดลิงก์ `https://โดเมนของคุณ/s/ชื่อร้าน` ในหน้าต่างไม่ระบุตัวตนเพื่อลองสั่งซื้อ

ตรวจการเชื่อมต่อฐานข้อมูลจาก SSH ได้ด้วย `npm run dbcheck`

## รันในเครื่อง (ไม่ต้องมี MySQL)
```bash
npm install          # ติดตั้ง mysql2 (ใช้เฉพาะตอนต่อ MySQL)
node server.js       # ใช้ไฟล์ SQLite ที่ data/zelly.sqlite  (ต้อง Node 22.5+)
npm test             # ทดสอบ logic + API
npm run test:e2e     # ทดสอบบนเบราว์เซอร์ (ต้องมี playwright)
```
เปิด http://localhost:3000 — ถ้าไม่ตั้ง `ADMIN_PASSWORD` ระบบสุ่มรหัสให้และพิมพ์ในหน้าจอ terminal

## ข้อควรรู้
- **รันแค่ 1 instance** (การล็อกเพื่อกันข้อมูลชนกันอยู่ในหน่วยความจำของโปรเซสเดียว) ซึ่งเพียงพอสำหรับ Node.js Web App ของ Hostinger
- ข้อมูลร้านบันทึกอัตโนมัติ ~1 วินาทีหลังแก้ไข (รวมข้อมูลจากหลายอุปกรณ์/พนักงานแบบรายรายการ ไม่ทับกัน) หากเน็ตหลุดจะมีแถบ "ยังบันทึกไม่ได้" และลองใหม่เอง
- รูปภาพ (สินค้า สลิป รูปแพ็ก) เก็บในตาราง `blobs` ของ MySQL สูงสุด 4MB/รูป — ถ้าใช้หนักมาก ควรเพิ่มพื้นที่ฐานข้อมูลหรือย้ายไปเก็บไฟล์ภายหลัง
- หน้าเว็บโหลดไลบรารี QR จาก cdnjs และฟอนต์จาก Google Fonts (ถ้าโหลดไม่ได้ QR จะไม่แสดง แต่ส่วนอื่นทำงานปกติ)
- **สำรองข้อมูล**: hPanel → phpMyAdmin → Export ฐานข้อมูลเป็นประจำ
- ตั้ง `TRUST_PROXY=0` ถ้ารันโดยไม่มี reverse proxy (ค่าเริ่มต้นเชื่อ `X-Forwarded-For` เพื่อจำกัดอัตราต่อ IP)
- ฝั่ง MySQL ผ่านการเขียนแบบเดียวกับ SQLite แต่ **ยังไม่ได้ทดสอบกับ MySQL จริง** ในสภาพแวดล้อมที่พัฒนา — ให้ทำ checklist ในข้อ 5 ก่อนเปิดให้ลูกค้าจริง

## โครงสร้างไฟล์
```
server.js            เซิร์ฟเวอร์ + ไฟล์หน้าเว็บ + งานล้างออเดอร์หมดเวลา
lib/                 db (MySQL/SQLite), model (กติกาธุรกิจ), diff (ซิงก์ข้อมูล), session, util, blobs
routes/              account (สมัคร/ล็อกอิน/พนักงาน/แพ็กเกจ), sync (บันทึกข้อมูลร้าน), public (หน้าร้านลูกค้า)
public/index.html    หน้าเว็บทั้งหมด (สร้างจากซอร์สของต้นแบบ)
scripts/dbcheck.js   ตรวจ DB    test/   ชุดทดสอบ
```
